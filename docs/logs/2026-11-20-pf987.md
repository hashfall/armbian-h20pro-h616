## WARNING do reset pulse (patch 0011)

```
------------[ cut here ]------------
WARNING: CPU: 3 PID: 43 at drivers/reset/core.c:483 reset_control_assert+0x168/0x1e0
Call trace:
 reset_control_assert+0x168/0x1e0 (P)
 sun8i_hdmi_phy_init+0x20/0x240
 sun8i_dw_hdmi_bind+0x268/0x450
```

Causa: o bootloader deixou o reset deassertado, mas o driver nunca chamou
`reset_control_deassert()`, então `deassert_count == 0`. O
`reset_control_assert()` dispara o WARN e **não** assere o reset. Por isso os
registradores externos da PHY continuam idênticos aos do boot:

```
ana1=00000f80 ana2=0c0040d8 ana3=02700203 pll1=000c6023
```

Correção para o próximo build: chamar `reset_control_deassert()` antes do
assert (ou usar `reset_control_reset()` com o contador já deassertado).

## Conclusão

- O patch `0005` **entrou**: o readback mudou de `06=0040 09=8039 0e=022b
  10=0019` para `06=0051 09=8009 0e=0230 10=001b`.
- O patch `0006` (`JTAG_PHY_CONFIG=0x10`) **entrou** e não mudou o resultado.
- O I2C da PHY funciona (os valores lidos são os escritos).
- O PLL continua sem travar (100 tentativas × 5 ms) em 172,78 MHz.
- O pulso de reset **não foi aplicado** (WARN do reset core).
- EDID continua zero; DDC sem resposta (o vendor usa `hdmi_skip_bootedid=1`).
